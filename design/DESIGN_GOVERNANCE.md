# くらしのしるし — 設計判断と共通トークンの運用基準

更新日: 2026-08-11
目的: 場当たり的な見た目修正を避け、情報の役割・危険度・操作性を先に決めてから、共通トークンと部品へ反映する。

## 1. 画面を作る順番

1. **役割と影響を定義する** — 何をする項目か、誤操作した時の重さはどの程度かを確認する。
2. **操作設計票を作る** — 目的、影響度、可逆性、失うもの、入口、実行、取り消し、合格条件を先に記す。
3. **情報をグループ化する** — 同じ目的・同じ頻度・同じ影響度のものだけをまとめる。
4. **操作の優先度を決める** — 主操作、補助操作、危険操作を分ける。危険操作は主操作の隣に置かず、折りたたみ＋確認を必須とする。
5. **レイアウトを決める** — 並列の重さが同じ場合だけ横並びにする。余白が余ったから並べる、はしない。
6. **共通部品を当てる** — 書体、色、角丸、アイコン、操作高さ、中央揃えをトークンから適用する。
7. **実表示で検証する** — 操作設計票の合格条件を、ローカルの実画面で満たすことを確認してからアプリへ反映する。ソース表示や低解像度スクリーンショットを確認方法にしない。

## 2. 書体トークンの責務

| トークン | 用途 | 使用例 |
|---|---|---|
| `functional` | 読む・押す・設定するための文字 | 見出し、ボタン、フォーム、設定、ナビゲーション |
| `expression` | 意図して紙面らしさを出す自由表現 | フリーボード内でユーザーが選んだ装飾テキストのみ |
| `number` | 金額・数値の読み取り | 金額、歩数、睡眠時間、グラフ数値 |

### 旧紙面トークンの移行

旧 `display` / `--ds-font-display` は操作画面の見出しにも使われ、明朝体が漏れる原因だった。互換用の旧名は**操作用ゴシック**へ退避する。新規実装では `expression` を明示した自由表現以外に明朝体を使わない。

## 3. 配置・中心揃えの契約

- 枠の中のアイコン・文字は、余白やベースラインではなく `grid` / `flex` の X・Y 中央を基準にする。
- 文字とアイコンが横並びの場合は、まず組全体を中央に置く。その後、意図的な強調が必要な時だけアイコンの拡大または文字のサイズ調整を行う。
- 同じ情報階層では、アイコン・文字・操作点を重ねない。追加アイコンはアイコン一覧とこの文書の責務に登録する。
- 基本文字は縦横比 1:1 を保つ。数字も同一の数値トークンを使い、個別に縦横を変形しない。

## 4. デザイン設定センターの情報構造

- **保存**: 現在の設定を端末へ保存する主操作。
- **入出力**: 設定を書き出す／読み込む。並列の補助操作。
- **初期設定に戻す**: 復元不能になり得る危険操作。通常は閉じ、確認してから実行する。

保存と初期化は概念的には対だが、影響度が違うため隣接させない。配置は最後に行う。

危険操作は、**説明を開く入口**と**実際に実行するボタン**を別部品にする。入口は説明を読むためだけに使い、初期化は展開後の専用ボタンと確認ダイアログを通ったときだけ実行できる。危険操作の外枠全体を実行範囲のように見せない。

## 5. 操作設計票と合格条件

操作を追加・変更するときは、[操作設計票と合格条件](OPERATION_DESIGN_SHEETS.md)に「役割・影響度・可逆性・失うもの・入口・実行・中止・実表示の合格条件」を残す。合格条件を満たすまで、横展開や公開を行わない。

## 6. 再発防止の確認項目

- 新しい見出しは `functional` トークンか。
- 古い `display` 経路から明朝が漏れていないか。
- 破壊的操作が保存の近くにないか。
- 危険操作の「入口」と「実行」が別部品になっているか。
- 操作設計票と実表示の合格条件を確認したか。
- 画面上の確認は実表示のローカル URL で行ったか。
- 変更理由、影響範囲、確認結果をこの文書群へ残したか。
- 再描画する操作を「位置保持」か「画面遷移」に分類し、[体調グラフと画面位置保持の契約](HEALTH_CHART_AND_SCROLL_CONTRACT.md)に従っているか。
