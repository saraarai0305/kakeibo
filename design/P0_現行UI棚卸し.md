# P0 現行UI棚卸し

目的: 既存データを維持したまま、旧UI・重複導線・競合する表示ルールを削除し、P1以降で「入口 → 目的 → 独立画面」へ置き換える。

## 保持するもの

- `localStorage["mainichi.v1"]` と `normalize()` を含む既存データ互換処理
- 支出・収入・口座・固定費・サブスク・予定・体調・習慣・テーマのデータモデル
- Gist同期、バックアップ、歩数／睡眠の取り込み設定
- `save()`、日付処理、金額計算、既存の入力値を読み書きする処理

## 置き換える画面構造

| 現在の構造 | 問題 | P1以降の置換先 |
|---|---|---|
| `data-tab` の `home/today/money/cal/body/pay` | 下部タブを中心にした旧構造とホームハブが共存する | ホームハブを唯一の入口にし、目的別の独立ページへ遷移 |
| `homeHub` の `root/record/today/analyze` | 新しい入口として残すが、導線の先に旧ページが残る | P2で大型リストボタンと統一ヘッダーに再構成 |
| `data-money-group` と `data-money-focus` と `data-money-view` | 3種類の状態で同じお金画面を切り替え、表示規則が競合している | `money:record/outlook/analysis` の単一ルート状態へ統合 |
| `data-body-view` と `data-body-focus` | 体調の記録と分析が同じ `#healthEntry` に混在する | `health:record/analysis` の独立画面へ分離 |
| `data-cal-focus` / `data-cal-browse` / `data-cal-day-mode` | 日・週・月・詳細の表示責務が散っている | `calendar:day` を主画面にし、週/月は展開状態だけにする |
| `data-today-more` と旧 `today` ページ | テーマ設定用のページと旧「今日」機能が混在する | テーマは独立ページへ、習慣とチェックリストは一日の流れの展開操作へ |

## 削除対象（P0で確認し、対応画面の置換時に削除）

| 対象 | 根拠 | 削除タイミング |
|---|---|---|
| 下部タブバー `.tabbar` と `data-gotab` 前提の見せ方 | ホームがハブである方針と矛盾する | P2でホームと共通ヘッダーを完成後 |
| `pay` を独立ページとして扱う構造 | 支払い予定はお金の見通しに属する | P3のお金画面置換時 |
| `moneyPortal` / `moneyOutlook` / 旧 `data-money-group` 群 | 同じお金情報が複数の枠・表示状態に重複する | P3で単一ルートに置換時 |
| `bodyPortal` と `#healthEntry` 内の切替表示 | 記録と分析の目的が一画面で競合する | P5の体調ページ置換時 |
| `calendarBrowse` を常時ページとして扱う構造 | 一日の流れを読む画面に週/月が常設される | P4で展開式カレンダーへ変更時 |
| `today` の二次情報・旧チェックリスト表示 | 一日の流れと重複し、説明・カードが増える | P4で一日の流れに統合時 |
| 旧文言・旧イベント・未使用CSS | スクリーンショットに古い操作が残る原因になる | 各P2〜P5完了前の検索で削除 |

## 現時点で確認した重複箇所

- ホームの「今日を整える」から、`cal` と `today` の2系統へ遷移している。
- お金は `data-money-section`、`data-money-focus`、`data-money-view` が同一DOMの表示を競合している。
- カレンダーには新しい3操作のほか、`details` 内に旧「予定を足す」・旧チェックリストの導線が残っている。
- 下部タブバーはホーム以外で残り、ホームハブを経由しない旧導線を提供している。
- `bodyPortal`、`moneyPortal` のポータル画面は、新しいホームハブと役割が重複している。
