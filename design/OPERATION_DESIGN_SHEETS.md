# 操作設計票と合格条件

更新日: 2026-08-11
目的: 画面の配置より前に、操作の役割・重さ・失うもの・確認方法を固定し、誤操作と場当たり的な調整を防ぐ。

## 使い方

新しい操作、または既存操作の役割・影響度を変える修正は、実装前に1件ずつこの票へ記録する。実表示で合格条件を満たすまでは、他画面へ横展開・公開しない。

| 項目 | 確認する内容 |
| --- | --- |
| ID / 対象画面 | 操作を一意に識別できる名前 |
| 目的 | 利用者が何を達成する操作か |
| 影響度 | 低・中・高。誤操作で受ける影響 |
| 可逆性 / 失うもの | 取り消せるか、何を失うか |
| 初期状態 | 最初に何を見せ、何を隠すか |
| 入口 | 説明や操作面を開くための操作 |
| 実行 | 状態を本当に変更する操作 |
| 中止 / 確認 | キャンセル、確認ダイアログ、復元方法 |
| 合格条件 | 実表示で確認する観察可能な条件 |

## DS-RESET-001｜初期設定に戻す

| 項目 | 内容 |
| --- | --- |
| 対象画面 | デザイン設定センター |
| 目的 | 見た目の調整値だけを初期値に戻す |
| 影響度 | 高い。利用者の調整作業を失う可能性がある |
| 可逆性 / 失うもの | 保存済みのデザイン調整を失う。`mainichi.v1` の生活データは失わない |
| 初期状態 | 保存・入出力と離れた位置に「危険な操作 / 初期設定に戻す」の小さな入口だけを表示する |
| 入口 | 入口を押すと、説明と専用の実行ボタンを表示する。入口自体では初期化しない |
| 実行 | 展開後の「初期設定に戻す」専用ボタンだけが確認ダイアログを開く |
| 中止 / 確認 | 確認ダイアログには「キャンセル」と「初期設定に戻す」を分けて表示する。キャンセルでは何も変えない |
| 近くに置く操作 | 説明文、生活データを削除しない注記、キャンセル |
| 離す操作 | 設定を保存、設定を書き出す、設定を読み込む |

### 合格条件

- [ ] 閉じた状態では、初期化のための大きな外枠や全幅の実行範囲がない。
- [ ] 入口を押しても設定値は変わらず、説明だけが開く。
- [ ] 実行ボタンは展開後だけに見え、入口とは別の押下領域である。
- [ ] 実ブラウザで閉じた状態の実行ボタンが非表示であることを確認する。
- [ ] 確認でキャンセルすると、値も画面状態も変わらない。
- [ ] 「生活データは削除しない」が読める。
- [ ] 320px幅以上の実表示で、保存・入出力と危険操作が近接して見えない。

## DS-SETTINGS-FILE-001｜設定ファイルの書き出し / 読み込み

| 項目 | 内容 |
| --- | --- |
| 対象画面 | デザイン設定センター |
| 目的 | 見た目の共通設定を端末間で移す |
| 影響度 | 書き出しは低い。読み込みは中程度（プレビューを置き換える） |
| 可逆性 / 失うもの | 読み込みは保存前のプレビューを置き換えるが、端末への確定保存前なら戻せる |
| 初期状態 | 「設定ファイル」グループの中に、書き出し・読み込みを並列で表示する |
| 入口 / 実行 | 各ボタンがそのまま実行入口。読み込みは保存前のプレビューであることを示す |
| 中止 / 確認 | 読み込み失敗時は既存プレビューを保つ。保存前なら初期値へ戻すことができる |

### 合格条件

- [ ] 書き出し・読み込みは同じグループで、初期設定に戻すとは離れている。
- [ ] 読み込み後、保存前は「プレビュー中」の状態であることが分かる。
- [ ] 画面幅に応じて1列になっても、役割の違う操作と混ざらない。

## UX-VIEWPORT-001｜再描画時の画面位置保持

| 項目 | 内容 |
| --- | --- |
| 対象画面 | 全画面 |
| 目的 | 保存・選択・削除で、利用者が見ていた場所を失わせない |
| 影響度 | 高い。入力途中や確認中の文脈を失わせる |
| 初期状態 | 操作後も現在のスクロール位置を保持する |
| 例外 | 戻る、別ページへ進む、ホームへ戻るは先頭から開く |
| 実装責務 | 共通描画関数が位置を保存・復元する。個別画面での先頭移動は禁止 |

### 合格条件

- [ ] 保存・選択・削除・表示切替の後、同じ画面位置に留まる。
- [ ] 戻る・ページ遷移・ホームへ戻るは先頭から開く。
- [ ] フリーボード操作後も、ページ位置を維持する。
- [ ] 実表示で、長い画面の中ほどから保存・削除・選択を確認する。

## DS-WORK-LOG-001｜仕事の記録（日報）

| 項目 | 内容 |
| --- | --- |
| 対象画面 | 独立した「仕事の記録」画面 |
| 目的 | 一日の作業・休憩・仕事の本文を残し、体調分析で生活データと比較できるようにする |
| 影響度 | 中。保存前の入力を失うと、その日の仕事の記録を失う |
| 可逆性 / 失うもの | 保存済みの日報は次回表示時に編集できる。保存前の未入力内容は保存操作で確定されるまで保持し、ページ遷移時には破棄する |
| 初期状態 | 当日の日付、空の入力欄、保存済み記録があればサマリーだけを表示する |
| 入口 | 「今日を整える」内の「仕事の記録」ボタン、またはホームのショートカット |
| 実行 | 「日報を保存」ボタン。開始・終了・休憩分を検証してから `S.workLogs[日付]` へ保存する |
| 中止 / 確認 | 戻る／ホームへ戻るで保存せず中止。入力不足は保存せず、画面位置と入力内容を保持する |
| 合格条件 | 実表示で、入力、保存、入力リセット、保存済みサマリー、同日分析への反映、PC/スマホ幅、スクロール位置を確認する |

## DS-WORK-LOG-002｜仕事の記録を体調分析へ連携

| 項目 | 内容 |
| --- | --- |
| 対象画面 | 体調の分析 |
| 目的 | 日報の作業時間・休憩時間を、睡眠・歩数・こころ・からだ・習慣と同じ日付軸で比較する |
| 影響度 | 低。分析表示の切替だけで、保存済みデータは変更しない |
| 可逆性 / 失うもの | 指標のオン／オフはいつでも戻せる。日報データは分析画面から削除しない |
| 初期状態 | 既存の分析指標に加えて作業時間・休憩時間を表示する |
| 入口 | 分析画面の指標切替ボタン |
| 実行 | 指標の表示／非表示を切り替える |
| 中止 / 確認 | 戻る、再度切替。未記録日は欠測として扱い、0分のデータを作らない |
| 合格条件 | 同じ日付の作業／休憩が正しい位置に表示され、個別切替でき、保存・切替後も画面位置を保持する |
### 実表示確認結果（2026-08-12）

- [x] ローカル実表示で「今日を整える」から独立した「仕事の記録」を開き、作業開始・終了、休憩、プロジェクト、日報テンプレートを確認した。
- [x] 390px幅の実表示で、入力欄・チェック欄・見出し・保存導線が重ならず、作業画面がゴシックで表示された。
- [x] 休憩分が作業時間を超える保存を実表示で拒否し、記録を変更しないことを確認した。
- [x] 体調分析の実表示で「作業時間」「休憩時間」を独立指標として表示し、未記録は「未記録」と表示した。
- [x] 実表示の分析グラフで、作業・休憩の表示切替を可視操作し、現在の画面位置を保持した。
- [x] 保存操作による利用者データの追加は行わず、実データを変更しない状態で確認した。
