# 操作設計票と合格条件

更新日: 2026-08-12
目的: 画面の配置より前に、操作の役割・重さ・失うもの・確認方法を固定し、誤操作と場当たり的な調整を防ぐ。

## 使い方

新しい操作、または既存操作の役割・影響度を変える修正は、まず既存の設計IDと同じ目的の票を検索してから記録する。同じ操作の票がある場合は新しい箱やIDを作らず、既存票へ追記する。実表示で合格条件を満たすまでは、他画面へ横展開・公開しない。

## DS-RESET-001｜初期設定に戻す

| 項目 | 内容 |
| --- | --- |
| 対象画面 | デザイン設定センター |
| 目的 | 見た目の調整値だけを初期値に戻す |
| 影響度 | 高い。利用者の調整作業を失う可能性がある |
| 可逆性 / 失うもの | 保存済みのデザイン調整を失う。`mainichi.v1` の生活データは失わない |
| 初期状態 | 保存・入出力と離れた位置に「危険な操作 / 初期設定に戻す」の小さな入口だけを表示する |
| 入口 | 入口を押すと、説明と専用の実行ボタンを表示する。入口自体では初期化しない |
| 実行 | 展開後の「初期設定に戻す」専用ボタンだけが確認ダイアログを開く |
| 中止 / 確認 | 確認ダイアログには「キャンセル」と「初期設定に戻す」を分けて表示する。キャンセルでは何も変えない |
| 近くに置く操作 | 説明文、生活データを削除しない注記、キャンセル |
| 離す操作 | 設定を保存、設定を書き出す、設定を読み込む |

### 合格条件

- [ ] 閉じた状態では、初期化のための大きな外枠や全幅の実行範囲がない。
- [ ] 入口を押しても設定値は変わらず、説明だけが開く。
- [ ] 実行ボタンは展開後だけに見え、入口とは別の押下領域である。
- [ ] 実ブラウザで閉じた状態の実行ボタンが非表示であることを確認する。
- [ ] 確認でキャンセルすると、値も画面状態も変わらない。
- [ ] 「生活データは削除しない」が読める。
- [ ] 320px幅以上の実表示で、保存・入出力と危険操作が近接して見えない。

### 次段階の整理順序

1. まず時間割分類（すべて／仕事／生活／共通）、仕事追加、仕事一覧の優先度分類を実装し、実表示で合格を確認する。

| 中止 / 確認 | チェックなしは保存しない。登録前に追加内容と元データを保持する説明を表示する。読み取り専用では実行不可 |
| 合格条件 | 既存候補の表示、優先度・状態付き登録、時間割・日報への同一項目反映、重複登録防止、390px/PC幅、位置保持、コンソールを実表示で確認する |

### 原因と再発防止

- 既存の `S.areas`／自由入力予定と新しい `S.workItems` の責務が分かれていたため、仕事一覧が空になった。
- 既存データをロード時に自動変換すると意図しない追加や優先度変更が起こるため、一覧内の明示的な登録入口で候補・優先度・状態を確認してから追加する。
- 仕事の同一性は表示名ではなく `workItemId` で保持し、自動時間割・日報選択・一覧が同じカタログを参照する。
- [x] 390pxのCodex実表示で「プラグイン開発」「ワンモーション」などの候補、優先度・状態、登録導線を確認した。
- [x] `tools/check.ps1` で既存仕事の登録、仕事一覧への反映、再登録候補からの除外、既存の時間割・日報連携を確認した。
