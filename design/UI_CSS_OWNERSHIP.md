# UI/CSS責務の所有表

更新日: 2026-08-12

旧UIと現行UIが同じHTML上に残る移行期間に、どの層へ修正を置くかを固定する。目的は、同じ画面へ別のCSSを足して中心・余白・書体を上書きする再発を止めること。削除は、DOM使用箇所・保存処理・実表示の確認が揃ってから行う。

| 層 | 現在の責務 | 新規修正の扱い |
| --- | --- | --- |
| `index.html` 内の基礎CSS | 旧データ画面の互換表示とアプリ起動前の最低限の基礎 | 現行画面の見た目を追加しない。移行完了後に旧DOMと一緒に削除候補へ分類する |
| `ui-v2.css` | 旧V2シェルのトークン・互換クラス | 新しい画面固有ルールを追加しない。既存データや旧イベントが参照しているか確認してから縮小する |
| `ui-analog.css` | 現行の `an-*` / `mr-*` 画面コンポーネントと画面構造 | 画面固有の構造・部品の正本。共通値をここへ重複定義しない |
| `ui-paper-baseline.css` | 全画面共通の色・書体・中心揃え・余白契約、Safari/PWAの表示補正 | 共通契約だけを置く。画面名を限定した見た目の例外を増やさない |
| `ui-v2.js` | `renderV2()` を唯一の描画入口とする現行ルート、保存・操作状態 | 画面遷移は `preserveScroll:false`、通常操作は位置保持。旧関数は使用箇所を確認してから段階的に統合する |

## 段階整理の合格条件

- [x] `window.newAppRender` が単一入口で、旧レンダーラッパーがない。
- [x] 日報、体調分析、保存・選択の自動検査が `tools/check.ps1` にある。
- [x] 現行CSSの読み込み順が `ui-v2.css` → `ui-analog.css` → `ui-paper-baseline.css` と明示されている。
- [ ] 旧UIのDOM・イベント・データ互換性を画面単位で確認し、旧CSSを削除する。
- [ ] `!important` の削減後に、PC・390px幅・Safari実機で全画面の中心と操作位置を再確認する。

## 変更前の確認

1. 対象画面が現行 `an-*` / `mr-*` か、旧互換画面かを確認する。
2. 共通契約なら `ui-paper-baseline.css`、画面固有なら `ui-analog.css`へ置く。
3. 新しい `!important`、画面固有の `scrollTo(0,0)`、文字記号による位置補正を追加しない。
4. `tools/check.ps1` とCodexの実表示で、保存・選択・削除・ドラッグの位置保持を確認する。

## AI分析前の責務固定（2026-08-13）

- `index.html`: 旧データ画面の互換表示とアプリ起動前の基礎。現行画面の見た目を追加しない。
- `ui-v2.js`: 現行画面の状態遷移・描画・イベント契約。`window.newAppRender`を唯一の描画入口とする。
- `ui-v2.css`: 現行画面の基本レイアウトと部品トークン。
- `ui-paper-baseline.css`: 現行画面に対する最終的な紙面・モバイル補正。画面固有の座標補正を増やさない。
- `tools/check.ps1`: 版・資産キャッシュ・構文・入口・主要導線の受入検査。Safari実機の代替ではなく、公開前の共通土台として使う。

旧UI互換処理は直ちに削除せず、参照が0になったことと実機受入を確認してから段階的に整理する。
