# 支出・収入を記録 — 承認済み実装仕様

更新日: 2026-08-08  
適用範囲: `moneyRecord` を視覚基準とし、全画面へ横展開する。

## 画面の優先順位

1. 今日使えるお金
2. 今残っているお金
3. 支出 / 収入の選択
4. 金額 → 方法 → カテゴリー → 保存
5. お金の見通し
6. 当日の記録
7. ホームへ戻る

## 配置規則

- 上部は、左に「戻る」、中央に三色バーのロゴと「くらしのしるし」、右に「設定」。操作枠は 58px とし、中央のブランドは残り幅の幾何学的な中心に置く。
- 日付と「くらしのしるし」は、その下の細い帯に左右配置する。実線と点線の間で縦方向の中心をそろえる。
- `MONEY LOG`、お金アイコン、ページ見出し、残高枠、入力欄、履歴は同じ左端にそろえる。
- 最終操作の「ホームへ戻る」は画面外に固定しない。ページ末尾に、アイコンと文字を一つの中央グループとして置く。
- 紙背景はページ末尾まで連続させ、スクロール時にも異なる背景色や唐突な切れ目を出さない。
- iOSで上下に引っ張ったときも、ページ外には同じ紙背景だけを見せる。
- 当日の記録は、カテゴリーと金額を同じ行の縦中心・左右端にそろえ、方法や時刻は表示しない。

## 文字・数字規則

- 基本文字は縦横比 1:1 を保つ。`scaleX`、`scaleY`、圧縮フォント、字形の変形は使わない。
- 日本語の本文・数字は `Hiragino Kaku Gothic ProN / Yu Gothic / system-ui` を基準とする。
- 小見出しは 12px、入力欄は 16px、主要操作は 17px、ページ見出しは 24px を基準とする。
- 金額は同じ書体・字幅の等幅数字を使う。通貨記号、符号、数字を同じ物理サイズにし、負号だけを光学補正として 1px 上へ置く。
- 金額の端数は画面では四捨五入して円単位で表示する。計算に使う元の値は変えない。
- 承認済み確認ページ `money-record-layout-approval.html` を金額表示の唯一の基準にする。「今日使えるお金」は 32px / weight 760、「今残っているお金」は 22px / weight 800、負の金額はコーラル `#D76A5F`。通貨記号と数字は同じサイズ・書体で表示する。
- 日付、くらしのしるし、`MONEY LOG`、入力ラベル、記録の補助情報は同じ 12px 階層にそろえる。

## 色規則

- 支出: 青 `#4D80AD`
- 収入・プラスの金額: 緑 `#4F986F`
- マイナスの金額: コーラル `#CA6258`
- 日用品など当日記録のカテゴリーには、三色バーと共通の小さな色チップを使う。

## 確認手順

- モックアップを返すときは、コード文字列ではなく UTF-8 の実表示ページをローカル URL で開く。
- 変更はまず一画面で実装し、スマホ幅の表示で上部と下部を別々に確認する。
- 承認後に限り、同じ設計規則をほかの画面へ適用する。

## 配信・実機確認規則

- 承認済み確認ページ `money-record-layout-approval.html` を実装の唯一の視覚基準にする。実機の見た目が異なる場合、基準ページを変えずに実アプリ側を一致させる。
- 公開ごとに `ui-v2.css`、`ui-analog.css`、`ui-v2.js` のURLへビルド番号を付ける。iPhone PWAが古いCSSだけを再利用して、HTMLと見た目が異なる状態を防ぐためである。
- Service Workerも同じビルド番号で再登録し、`updateViaCache: "none"` を使う。公開確認は `version.txt` が対象ビルドを返してから行う。

## 直接移植・実表示確認規則（2026-08-08追加）

- 承認済み確認ページは、CSSだけを旧コンポーネントに重ねない。ヘッダー、残高、タブ、フォーム、見通しボタン、履歴、ホーム導線を同じDOM構造と寸法で実アプリへ直接移植する。
- 旧コンポーネントの親グリッド・余白・幅を残すと、ローカル確認とiPhone実表示の差になる。承認対象のページでは旧クラスを継承しない専用の構造を使う。
- 各ページは「確認用の実表示」→「スマホ幅の実アプリ表示」→承認の順で確認する。HTMLコードをブラウザに直接表示しない。
- 残高の右端金額は、ラベルと同じグリッド行に置く。汎用スタイルの `grid-column: 1 / -1` を引き継がない。

## 全画面への横展開規則（2026-08-08追加）

- 承認済みの支出・収入画面を、全画面の唯一の視覚基準とする。旧V2の親グリッドやカード寸法を再利用せず、各画面を専用の紙面構造で直接構成する。
- ページ共通の骨格は「左: 戻る / 中央: 三色バー + くらしのしるし / 右: 設定」「日付帯」「英字の区分名 + 日本語見出し」「本文」「ページ末尾のホームへ戻る」とする。
- ホームだけはハブとして扱い、戻る・設定・ホームへ戻るを置かない。情報や数値は置かず、3つの入口だけを大きく見せる。
- 入口画面、見通し、分析、こころとからだ、一日の流れ、チェックリスト、テーマ、週/月、設定は、同じ余白・角丸・操作高・文字階層を使う。
- 1画面の主役は1つに限定する。重要情報は紙面の面、補助情報は区切り線、選択肢は角丸の操作列で分ける。旧来の多重カード表示は禁止する。
- 支出は青 `#4D80AD`、収入・プラスは緑 `#4F986F`、マイナスはコーラル `#D76A5F`、今日/テーマは黄、こよみは紫を使う。
- 操作枠は 58px、主要操作は 54px 以上、補助操作は 42px 以上とし、アイコンと文字は各枠の X/Y 中心を取り、文字はアイコンの下に置く場合も同じ中心線を使う。
- 画面下部には固定ボタンを置かない。ホームへ戻るは本文の最後に置き、紙背景をその下まで連続させる。iOSの上下オーバースクロールでも暗い背景や切れ目を見せない。
- 画面を確認する際は、HTMLソースを表示せず、UTF-8で配信した実表示URLを開く。承認用画面と実アプリを同じスマホ幅で比較し、差異は実アプリ側だけを直す。

## 実装確認の固定手順（2026-08-08追加）

- 承認済みページを横展開するときは、最初に親シェルの最大幅を 390px に固定する。旧シェルの 560px 基準を残したまま子要素だけを 390px にすると、中央寄せ・左右端・入力幅がずれる。
- 変更後は、ホーム、記録、支出・収入、こころとからだ、一日の流れ、見える化、設定を実描画する。コードの文字列・DOMの断片だけでは確認完了としない。
- 各画面で確認する順番は「上部ヘッダー → 見出しの左端 → 主操作 → ページ末尾のホーム導線 → 紙背景の連続」。上端・下端・横端のいずれにも暗い背景や別色の余白を残さない。
- 設定や分析も専用画面であり、旧い汎用カードを追加しない。必要な情報は、紙面の面・区切り線・角丸の操作列へ役割ごとに分解する。

### 借入の扱い（2026-08-12）

- 借入は収入ではなく、返済義務のある資金として金銭記録内の独立タブで扱う。
- 借入の保存モデルは `S.borrowings`。見通しの「今残っているお金（借入を含む）」には加算するが、収入合計・傷病手当の見込み・収入分析には加算しない。
- 読み取り専用PCでは保存せず、記録端末（iPhone）で保存してからPCへ同期する。
