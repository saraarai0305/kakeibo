## 設計判断ログの扱い

`DESIGN_DECISION_LOG.md` は、既存の正本を置き換える文書ではありません。
利用中のフィードバックをまず漏れなく残す**時系列の受付簿**です。判断が定着したら、該当する A または B の正本へも反映します。
書体・配置・設定操作の横断ルールは `DESIGN_GOVERNANCE.md`、画面ごとの仕様は B の正本だけを参照します。日付入りの移行メモは履歴であり、正本にはしません。

## 変更の標準手順

1. **探索** — `design/`、`docs/`、必要な `private/` を画面名・操作名・設計ID・版で検索し、既存の記録箱を特定する。
2. **記録** — 利用者の指摘・提案・違和感を既存の設計判断ログへ残す。既存の操作票や正本がある場合はそこへ追記し、新しい箱を作らない。
3. **整理** — 目的、役割、影響度、可逆性、誤操作時の損失を確認する。
4. **操作設計票** — 既存IDを優先し、入口、実行、確認・中止、合格条件を定義する。
5. **規則化** — 共通なら A、画面固有なら B の正本に判断を反映する。
6. **配置** — 意味と重さが近い操作だけを並列にし、最後に余白・中央揃え・形を決める。
7. **実表示確認** — コード表示や圧縮スクリーンショットではなく、実際の確認ページで合格条件を確認する。
8. **公開** — 実データで動作確認してから公開する。
