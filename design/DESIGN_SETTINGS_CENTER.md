# デザイン設定センター（基盤仕様）

更新日: 2026-08-11
対象: くらしのしるし / `design-studio.html`

## 目的

コードを編集できない人でも、画面ごとにばらばらな見た目を作らず、共通ルールに沿って調整できるようにする。

## 変更する場所

- アプリ本体: `index.html`
- 別画面の設定センター: `design-studio.html`
- 設定データ: ブラウザの `kurashi-no-shirushi.design-tokens.v1`
- 生活データ: `mainichi.v1`（設定センターは変更しない）

## 調整できる共通項目

| グループ | 調整できるもの | 反映範囲 |
| --- | --- | --- |
| 色 | 背景、面、文字、線、青・緑・コーラル・紫 | 全画面 |
| 文字 | 基本文字、見出し、数字、サイズ、字間 | 全画面 |
| レイアウト | 左右余白、まとまり間隔、操作の高さ、角丸 | 共通部品から順番に移行 |
| アイコン | 大きさ、座布団の大きさ | 共通アイコン |
| 動き | 有効/無効、時間、強さ | 共通アニメーション |

## ルール

1. 見た目の数値は新規画面で直接書かず、まず `design-system.js` のトークンとして定義する。
2. 生活データ・同期トークン・ヘルスケア受信データを、デザイン設定から変更しない。
3. 枠内は文字のベースラインではなく、`grid` / `flex` の領域中央で配置する。
4. アイコンと文字を横に並べるときは、まず全体を光学的に中央に揃え、意図がある場合だけ片方を強調する。
5. 基本文字・数字は縦横比を変形しない。数字は同じ書体・ウェイトを使う。
6. 新しいアイコンはSVGを基本とし、アイコン一覧と用途を同時に更新する。
7. 新規の画面や修正は、本体に反映する前に実表示の確認URLで確認する。コードだけを表示して確認完了にしない。
8. 設定画面を含む機能画面の見出し・操作・数値には UI ゴシックを使う。明朝系はロゴや利用者が選択した自由表現だけに限定する。
9. 書体トークンは、操作用（functional）・自由表現用（expression）・数字用（number）に分ける。旧 `display` / 紙面用トークンを新規UIから直接参照しない。

## 設定の扱い（情報構造）

設定操作は、横幅に収まるかどうかではなく、役割・影響度・可逆性の順に構成する。

| グループ | 操作 | 扱い |
| --- | --- | --- |
| 保存 | 設定を保存 | 日常の主操作。プレビュー中の値をこの端末に確定する。 |
| 設定ファイル | 設定を書き出す / 設定を読み込む | 同じ入出力グループに並べる。読み込みはプレビューとして反映し、保存前に確認を挟む。 |
| 初期化 | 初期設定に戻す | 調整を失う高影響操作。主操作から離し、折りたたみと確認を必須にする。 |

- スライダー等の変更は **プレビュー中** とし、`設定を保存` を押したときだけ端末へ確定保存する。
- 読み込みは現在のプレビューを置き換えるため、実行前に確認する。読み込んだだけでは保存済み設定を上書きしない。
- 初期化は生活データを削除しないことを画面上で明示する。

### 初期設定に戻す専用部品

「初期設定に戻す」は通常のボタン群と同じ部品・同じ幅で扱わない。危険操作の専用部品として、次の順序を固定する。

1. 最初は「危険な操作 / 初期設定に戻す」の小さな開閉入口だけを表示する。
2. 開閉入口を押しても初期化は実行しない。説明と専用の実行ボタンを表示するだけにする。
3. 専用の実行ボタンを押したときだけ、生活データを削除しないことを含む確認ダイアログを出す。
4. 確認ダイアログの「キャンセル」は常に初期位置へ戻し、初期化しない。
5. 保存・入出力から視覚的にも操作的にも離す。外枠全体を初期化の実行範囲のように見せない。

この部品の判断根拠と合格条件は [操作設計票と合格条件](OPERATION_DESIGN_SHEETS.md) の `DS-RESET-001` を正本とする。

## 書体トークンとフォントについて

| 役割 | 使う場所 | 設定センターでの項目 |
| --- | --- | --- |
| `functional` | 画面見出し、フォーム、ボタン、設定、数値以外の操作情報 | 操作用の書体 |
| `expression` | 自由ボード内で利用者が選ぶ文字など、意図的な表現 | 自由表現の書体 |
| `number` | 金額、歩数、時刻、グラフの数値 | 数字 |

旧 `display` は旧設定の移行専用です。既存の選択は `expression` に引き継ぎますが、操作画面の書体には使いません。

ブラウザは利用者のPCに入っている全フォントを安全に一覧取得できない。さらにPCのローカルフォントはiPhoneに自動配布されない。

- 設定センターで選べるもの: iPhone/PCで利用可能な安全なフォールバック群
- 将来、同じフォントを全端末で使う場合: 利用許諾を確認したWebフォント（WOFF2）を同梱する
- 「このPCだけで試す」書体: 設定センターの将来拡張で個別指定を追加できるが、iPhone再現は保証しない

## 実装・確認の順序

1. デザイン設定センターで値を変え、プレビューを確認する。
2. 代表ページ（支出・収入を記録）へ反映し、実表示で確認する。
3. ヘッダー、戻る、ホームへ戻る、フォーム、分析、フリーボードの共通部品へ横展開する。
4. `tools/check.ps1`、実機幅、iPhone PWAで確認する。
5. 公開時にサービスワーカーのキャッシュ名・対象ファイルを更新する。

## 今回の範囲

- デザイン設定データの単一ソースを追加
- 本体が設定データを読み込む基盤を追加
- 別URLの `design-studio.html` を追加
- 既存の生活データを保持

次の段階で、現在の既存CSSに残る画面固有値を共通トークン・共通部品に置き換える。

## 確認の原則（再発防止）

- 設定画面や確認ページは、**HTMLコードではなく実表示のページ**をブラウザで開いて確認する。
- 実装前に、対象ページ・比較する基準ページ・確認する項目を明確にする。
- 実装後は、同じURLで「設定センター → 本体の代表画面」の順に実表示を確認する。
- 画面固有の余白・フォント・色を先に直接直さない。まず共通トークンで直せるか判断する。
- 例外が必要な場合は、例外の理由・対象画面・再確認項目を `design/` 配下の記録に残す。

## 誰でも調整できる範囲

設定センターでは、コードを編集せずに次を変更できる。

- 色（背景、面、文字、線、青・緑・コーラル・紫）
- 基本文字・見出し・数字の書体
- 文字の大きさと文字間隔
- 左右余白、まとまりの間隔、ボタン・アイコンの大きさ
- 角丸、動きの有無・時間・強さ

変更はこの端末に保存され、本体を開き直すと反映される。複数端末へ同じ見た目を配る場合は「設定を書き出す」でJSONを保存し、他端末の設定センターで「設定を読み込む」を使う。
