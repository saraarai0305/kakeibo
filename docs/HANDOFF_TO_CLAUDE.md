## 重要なデータ契約

- 日報は `D:\仕事用\会社\板\日報\YYYY-MM-DD.json` の
  `mainichi.daily-report.v1`を読む。
- 日報のプロジェクト名・仕事内容・振り返りは取り込むが、スマホ側で入力した
  開始・終了・休憩・実作業時間は保持する。日報側の時間で上書きしない。
- プロジェクト別の作業時間は推測配分しない。時間は日全体の値として扱う。
- 日報で複数案件を選んだ場合も、案件別の時間を入力しない限り割合を表示しない。
  日報で入力した案件別実作業分を根拠に、合計に対する割合だけを表示する。
- 2026-08-30、毎日自動生成される仕事枠（プラグイン開発・生活管理アプリ・ワンモーション）を、
  今日以降だけ停止した。過去の日報・案件カタログ・日報実績は残っている。
- 2026-09-03、ホームはスマホ版の現行レイアウトへ戻した。順序はショートカット→仕事／生活／見える化で、各入口の導線・枠サイズは変更していない。
- 2026-08-30として誤記されていた日報は、内容を変えず2026-08-29へ訂正済み。
  現在の正しいファイルは `D:\仕事用\会社\板\日報\2026-08-29.json`。
- 利用者データは端末側に保存されるため、実機の既存データを初期化・全体上書きしない。

- 日報のファイル選択→プレビュー→明示取り込み／既存日報の明示上書き。
- 共有APIからの未確認日報の受信と、確認後の取り込み。
- 23:59の歩数自動保存導線、手動入力・変更の保持。
- 仕事の毎日固定予定を今日以降だけ解除する操作。

- 支払い種類・カテゴリの追加、編集、削除。削除後も過去記録は保持。
- iPhone幅の日時・カード・入力枠の配置調整。

## 引き継ぎ後の最初の確認

1. `git status`で未コミット変更を確認し、既存の利用者データを触らずに自動検査を実行する。
2. 日報取り込みで、プロジェクト名と内容だけが反映され、スマホ側の時間が残ることを確認する。
3. PC幅と390px幅で、日報・時間割・体調・設定の表示を確認する。
4. 変更を公開する場合は、検査結果を残してからコミット・プッシュする。

## 引き継ぎ時の一言

このアプリは、記録を増やすことよりも、利用者がその日の実情を無理なく残し、
後から根拠を確認できることを優先する。既存の端末データと日報本文を失わないことを
最優先に、設計判断は共通原則と設計ログへ追記してから変更する。
