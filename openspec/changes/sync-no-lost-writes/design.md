## Context

同期先は GitHub の Gist（ファイル mainichi-data.json）。書き込みの口は2つ生きている（index.html）:

- `pushRemote`: 読む（GET）→ `reconcileSync` で3者（前にそろえた姿・この端末・同期先）を足し合わせ → 版を指定せず PATCH
- `pushImportedWorkLog`: 日報の取り込み。読む → その日だけ足す → 版を指定せず PATCH
- ほかの PATCH 2か所（旧受信箱）は `if(false && …)` で止まっている。明示の復元は `syncReplacePending` で `pushRemote` を通る

読んでから PATCH までの間に別の端末が書くと、後の PATCH が先の書き込みを消す。Gist の REST の PATCH に「この版の時だけ」の保証は書かれていない（If-Match を足すだけでは済みにしない）。
同じ項目を2台が変えた時は `mergeSyncData` が `savedAt` の新しい側を黙って選ぶ。

## Goals / Non-Goals

**Goals:** 同時に保存しても、別々の記録は両方残る。同じ項目の食い違いは両方残して持ち主が選ぶ。送り直しで二重に入らない。日報の取り込みと iPhone の打刻が同時でも、スマホの時刻を上書きしない。
**Non-Goals:** 本番の切り替え・公開・実データの移し（試しの後に持ち主が決める）。ヘルスケアの受信。画面の作り直し。

## Decisions

**同期先の置き場＝A Durable Object に決まった（社長 2026-11-10 10:04「Cloudflare に移す案で進めてください」）**

| 案 | 中身 | 良い所 | 弱い所 |
|---|---|---|---|
| A（推し）Durable Object | push-server（Cloudflare Workers）に同期の箱を1つ足す。「版を比べて保存」を1つの手順の中で行い、版が違えば断る | 保証が同期先の側にある。通知サーバーで同じ作り（DailyReportInbox など3つ）を既に使っている | 家計・体調を含む全データの置き場が GitHub から Cloudflare へ移る。切り替えと戻し方が要る |
| B Gist のまま | 保存の後に Gist の履歴を読み、自分が読んだ版の直後でなければ、間の版を読んで足し合わせて送り直す | 置き場が変わらない | 後から見つける形。送り直しの前にアプリが閉じると、次の同期で消えた側を「消した」と読む恐れが残る |

- 置き場の約束（push-server の SyncSpace）: `POST /v1/sync/spaces`（通知サーバーにつないだ端末の鍵で作る・置き場の鍵を作った端末に一度だけ返す）／`GET /v1/sync/spaces/{id}/state`＝`{version, content}`／`PUT` は `If-Match: "<読んだ版>"` と `X-Mainichi-Request-Id` が要る。版が違えば 409 `{conflict, version, content}`、If-Match が無ければ 428。直近10版の写しを箱の中に残す（戻すため）
- アプリの読み書きは `syncRead`・`syncWrite` だけを通す。同期の設定に `mode: "cloud"`（`cloudBase`・`spaceId`・`spaceSecret`）があれば置き場、無ければ今までの Gist
- 端末は送っていない変更を「未送信」として手元に持ち、保存が断られたら消さずに読み直す（S と前にそろえた姿を、通るまで書き換えない・送り直しは3回まで）
- 要求ごとに端末が ID を付け、同期先は同じ ID の2回目を同じ答えで返す（二重に入れない）
- 同じ項目の食い違いは、両方の値を `syncConflicts` に退避して、持ち主が選ぶまで消さない
- 画面の型（UI PATTERNS・2026-11-10 当席が選んだ・社長はまだ見ていない）:
  - 選んだ: **リンク付き型 告知バー**（envydesign.jp/patterns/parts/announce-bar 系）＝食い違いが1件でもある間だけ、どの画面でも上に1行「同期で食い違いが N 件あります」を出し、押すと選ぶ所が開く
  - 選んだ: **選択肢型 ボトムシート**（envydesign.jp/patterns/sheet-picker/）＝1件ごとに「いま使っている値」と「退避した値」を縦に2枚並べ、違う欄だけ色を付ける（差分強調型 テーブルの考え方を2枚の札に移す）。押したらその値にそろえて閉じる
  - 見た目は今の設定の画面と同じシート（全画面の .sheet）を使う＝下から半分で出す形にはしていない（アプリの中でシートの形を2つに増やさない）
  - 選ばなかった: ベル型 通知（ヘッダーにベルが無い・見に行かないと気づかない）／確認ダイアログ型 モーダル（元に戻せない操作の前の確認向け＝選ぶ所ではない）／差分強調型 テーブルそのもの（390px で2列の表は狭い）
- 退避の形: `S.syncConflicts = [{id, path, fields, values:[いま使っている値, 退避した値], chosen:0, at}]`。path は食い違った欄を含む一番近い記録（ID の付いた並び）まで。同じ食い違いはどちらの端末で見つけても同じ id（path と2つの値から作る）になり、足し合わせで1件にまとまる。時刻の欄（savedAt・updatedAt・importedAt・lastScheduled）と syncConflicts 自身は数えない
- 選んだら: その記録を選んだ値で置き換え、その件を syncConflicts から外して保存する（ふだんの保存＝同期で相手にも届く）。値を選ばずに閉じても消さない

## Risks / Trade-offs

- 利用者のデータが消える・上書きされる道に触る。戻し方: 切り替えの前に、今の Gist の中身を別の名で退避し、件数を照らし合わせる。新しい同期先を止めれば、今の Gist の同期に戻せるようにする（新旧のアプリが混ざる間に旧い口から書いた分も拾う）
- 試しは偽の同期先と試しのデータだけで行う。実データ・本物の鍵は使わない
- PC は今、読み取り専用（Codex 11-07）。試しの間もそのままにする
