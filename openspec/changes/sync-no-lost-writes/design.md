## Context

同期先は GitHub の Gist（ファイル mainichi-data.json）。書き込みの口は2つ生きている（index.html）:

- `pushRemote`: 読む（GET）→ `reconcileSync` で3者（前にそろえた姿・この端末・同期先）を足し合わせ → 版を指定せず PATCH
- `pushImportedWorkLog`: 日報の取り込み。読む → その日だけ足す → 版を指定せず PATCH
- ほかの PATCH 2か所（旧受信箱）は `if(false && …)` で止まっている。明示の復元は `syncReplacePending` で `pushRemote` を通る

読んでから PATCH までの間に別の端末が書くと、後の PATCH が先の書き込みを消す。Gist の REST の PATCH に「この版の時だけ」の保証は書かれていない（If-Match を足すだけでは済みにしない）。
同じ項目を2台が変えた時は `mergeSyncData` が `savedAt` の新しい側を黙って選ぶ。

## Goals / Non-Goals

**Goals:** 同時に保存しても、別々の記録は両方残る。同じ項目の食い違いは両方残して持ち主が選ぶ。送り直しで二重に入らない。日報の取り込みと iPhone の打刻が同時でも、スマホの時刻を上書きしない。
**Non-Goals:** 本番の切り替え・公開・実データの移し（試しの後に持ち主が決める）。ヘルスケアの受信。画面の作り直し。

## Decisions

**持ち主が決めること: 同期先の置き場（試しは両方の候補で進められる）**

| 案 | 中身 | 良い所 | 弱い所 |
|---|---|---|---|
| A（推し）Durable Object | push-server（Cloudflare Workers）に同期の箱を1つ足す。「版を比べて保存」を1つの手順の中で行い、版が違えば断る | 保証が同期先の側にある。通知サーバーで同じ作り（DailyReportInbox など3つ）を既に使っている | 家計・体調を含む全データの置き場が GitHub から Cloudflare へ移る。切り替えと戻し方が要る |
| B Gist のまま | 保存の後に Gist の履歴を読み、自分が読んだ版の直後でなければ、間の版を読んで足し合わせて送り直す | 置き場が変わらない | 後から見つける形。送り直しの前にアプリが閉じると、次の同期で消えた側を「消した」と読む恐れが残る |

- 端末は送っていない変更を「未送信」として手元に持ち、保存が断られたら消さずに読み直す
- 要求ごとに端末が ID を付け、同期先は同じ ID の2回目を同じ答えで返す（二重に入れない）
- 同じ項目の食い違いは、両方の値を `syncConflicts` に退避して、持ち主が選ぶまで消さない
- 画面の型（UI PATTERNS）: 選ぶ所の型は、作業 3.2 に入る前に選んでここに書く（いまは未選定）

## Risks / Trade-offs

- 利用者のデータが消える・上書きされる道に触る。戻し方: 切り替えの前に、今の Gist の中身を別の名で退避し、件数を照らし合わせる。新しい同期先を止めれば、今の Gist の同期に戻せるようにする（新旧のアプリが混ざる間に旧い口から書いた分も拾う）
- 試しは偽の同期先と試しのデータだけで行う。実データ・本物の鍵は使わない
- PC は今、読み取り専用（Codex 11-07）。試しの間もそのままにする
